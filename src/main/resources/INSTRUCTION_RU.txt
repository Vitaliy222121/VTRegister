================================================================================
  VTRegister — инструкция (коротко и по делу)
================================================================================

0. УСТАНОВКА ЗА 1 МИНУТУ
   * Положи VTRegister.jar в plugins/ сервера (Paper/Spigot/Purpur/Folia и
     форки, версии 1.13 → 1.21.x → 26.x и новее; Java 8 → 25 — см. п.11).
   * Запусти сервер — создадутся config.yml, advanced.yml, lang/ru.yml, lang/en.yml.
   * Всё уже настроено «из коробки». Обычно менять ничего не нужно: по
     умолчанию включены защищённый ввод пароля, Argon2id и лёгкий антибот
     (физика падения + пазл) сразу при входе.
   * Простой сервер — оставь как есть. Продвинутый — включи нужные этапы и
     функции сам (antibot.stages, email, twofactor, базы данных, прокси).
   * Есть прокси (Velocity/BungeeCord)? Этот ЖЕ jar кладётся и на прокси — см. п.7.
   * Обновление плагина: просто замени jar. Новые настройки и тексты допишутся
     сами, твои значения и комментарии не сбиваются. Случайно удалил строку —
     она вернётся при следующем запуске со значением по умолчанию.

1. КАК УСТРОЕНА ПРОВЕРКА НА БОТА
   Новый игрок попадает в отдельный пустой мир (auth_verify) и проходит этапы.
   Какие этапы включены — antibot.fast_stages (быстрый режим, по умолчанию
   [fall, puzzle]) или antibot.stages (обычный режим) в config.yml:
     fall    — физика: 5 повторов по умному плану (обычное падение, высокое
               падение с разгоном, паутина, подброс вверх, ещё падение —
               порядок случайный). Бот, умеющий один сценарий, ломается на другом.
     puzzle  — «убери лишние картинки»: картинки каждый раз случайные.
     block   — пройди по пути, ОТКРОЙ И ЗАКРОЙ сундук у старта, возьми
               инструмент и сломай нужный блок, подбери выпавшее.
     click   — нажать кнопку «Я НЕ БОТ» среди кнопок-обманок; кнопки при
               каждой отправке встают в новом случайном порядке, цвета —
               antibot.click_buttons (как в lang / свои / один цвет / без цвета).
     captcha — код на карте в руке. antibot.captcha_strike: true — «зачёркнутая»
               капча: линии через текст мешают программам, человек читает.
               По умолчанию выкл.
     air_captcha — (по умолчанию выкл) игрок висит в воздухе и крутит камерой —
               появляется код из крупных разноцветных блоков на весь экран, по
               случайной диагонали; код вводится в чат. Размер — air_captcha.scale.
     math    — пример на сложение (умножение — antibot.math_operations).
     secret / camera / slots — дополнительные этапы.
   Новые игроки проверяются всегда, постоянные — снова раз в 24 часа
   при входе (recheck_hours: 24; 0 — не перепроверять).
   Bedrock-игроки (Geyser/Floodgate) проверяются мягче — их физика другая.
   Клиенты любых версий: 1.8 → новейшие через ViaVersion + ViaBackwards
   (1.7 — ещё ViaRewind), на сервере или на прокси.

2. РЕЖИМЫ ПРОВЕРКИ
   По умолчанию: antibot.fast_mode: true — быстрый режим: проверка СРАЗУ при
     входе, без очередей и без шага «сдвинься с места»; этапы — antibot.fast_stages
     (физика + пазл). Лишние сверх fast_max_concurrent ждут на месте с боссбаром.
   antibot.fast_mode: false — обычный режим: если проверок больше
     max_concurrent_checks, лишние ждут с боссбаром (queue_mode: bossbar).
   queue_mode: lobby — лобби-ожидание с паркуром и PvP-зоной (п.4).

3. БАНЫ И ЛИМИТЫ (защита от наплыва ботов)
   antibot.bans (mode: auto) — бан IP только ПО ФАКТАМ:
     * Доказанный провал — неверная физика, флуд пакетами, робот-ответы
       (слишком быстро/ровно), кнопка-обманка, ошибка в пазле или на блоке.
     * Таймаут, лаг, AFK — НЕ доказательство: только кик, бана нет никогда.
     * Первые 2 доказанных провала — только кик (free_fails: 2): человек мог
       ошибиться. С 3-го — бан IP: 1 минута, потом 5, потом 15 (tiers_minutes).
       Навсегда — только если permanent: true (по умолчанию ВЫКЛ).
     * Ошибка в пазле или на блоке — сразу кик (puzzle_max_wrong / block_max_mistakes).
       Попыток ввода капчи — captcha_attempts (3).
     Баны переживают рестарт. Снять все баны: /authadmin unban
   antibot.connection_limit — сколько подключений пускать в секунду и в минуту,
     всего и с одного IP. Уже зарегистрированных не трогает (registered_bypass).
   antibot.guard — остальное: attack-mode при всплеске, лимит онлайна с IP,
     фильтр ников (Bedrock-ники с «.» пропускаются).

4. ЛОББИ-ОЧЕРЕДЬ И PvP-ЗОНА (только при queue_mode: lobby)
   Общая платформа ожидания: паркур, PvP-зона (queue_pvp), голограмма.

5. ЕДИНЫЙ ЧЁРНЫЙ СПИСОК МЕЖДУ СЕРВЕРАМИ (global_blacklist, по умолчанию ВЫКЛ)
   Серверы-партнёры обмениваются банами: бот или читер, забаненный на одном
   сервере, не заходит на другие. Как соединить два сервера:
     1) На обоих: global_blacklist.enabled: true и своё server_name.
     2) Сервер, который ОТДАЁТ список: publish.enabled: true, открыть порт
        publish.port (8765) в файрволе хостинга. Токен (пароль доступа)
        появится в plugins/VTRegister/data/blacklist-token.txt — отдай его партнёру.
     3) Сервер, который ЗАБИРАЕТ: в peers добавить
          - url: "http://IP-партнёра:8765/vtregister/blacklist"
            token: "токен партнёра"
   Отдаются: баны антибота от 3-й ступени (share_from_tier) и баны сервера
   (/ban, /ban-ip — например за читы; share_server_bans). Только IP/ники и
   срок бана — никаких паролей и других данных.

5.1 ЗАЩИТА ОТ БОТОВ НА ВХОДЕ (всё включается/выключается в config.yml)
   antibot.ping_check      — настоящий клиент сначала видит сервер в списке
                             серверов; бот подключается сразу. mode: attack —
                             только во время атаки (по умолчанию), always — всегда.
   antibot.datacenter_block — запрет входа с IP хостингов/VPN (список скачивается
                             сам, по умолчанию ВЫКЛ).
   antibot.surge           — режим наплыва: при волне входов проверки стартуют
                             дозированно, остальные ждут с боссбаром — без лагов.

5.2 ЗАЩИТА АККАУНТОВ
   2FA (Google Authenticator, Яндекс Ключ, Aegis…): /2fa on → в руку выдаётся
     карта с QR-кодом → в приложении «+» → «Сканировать QR» → ввести /2fa 123456.
     Нет места в хотбаре или не сканируется — ниже в чате ключ (клик копирует),
     его можно ввести в приложении вручную. /2fa cancel — отмена, /2fa off — выкл.
     Одноразовые коды меняются каждые 30 сек, один код дважды не сработает.
   twofactor.force_admins — обязательная 2FA для админов. По умолчанию ВЫКЛ
     (админа за это не кикает). Включишь — админ без 2FA сможет только /2fa on.
   security.login_log      — журнал входов: logs/logins/ГГГГ-ММ-ДД.log.
   security.admin_alerts   — оповещение в Discord/Telegram, когда админ входит
     с нового IP (впиши вебхук Discord или токен бота + chat_id Telegram).
   Пароли хешируются Argon2id; один аккаунт — одна сессия (второй вход с
     того же ника не выбивает первого).

5.3 ПОЧТА (привязка /email и восстановление пароля /recover)
   1) config.yml → email.enabled: true
   2) email.provider: gmail | yandex | mailru — сервер, порт и SSL подставятся
      сами. Свой почтовый сервер — provider: custom и заполнить smtp вручную.
   3) smtp.user — твой адрес, smtp.password — ПАРОЛЬ ПРИЛОЖЕНИЯ (не обычный):
        Gmail   — включи двухэтапную проверку → myaccount.google.com/apppasswords
        Яндекс  — id.yandex.ru → Безопасность → Пароли приложений → «Почта»;
                  в настройках Яндекс Почты разреши доступ почтовым программам
        Mail.ru — Настройки → Безопасность → Пароли для внешних приложений
   4) /authadmin reload, затем проверка: /authadmin testmail <твоя почта>
      Не пришло — команда покажет причину (неверный пароль, порт, сертификат).
   Игрок: /email <адрес> → код приходит на почту → ввести в чат или /email 123456.
   Забыл пароль: /recover — код придёт на привязанную почту → /recover <код> <новый пароль>.

6. AFK
   До входа: кто ничего не делает — кикается (ввод пароля = активность).
   После входа плагин за AFK НЕ кикает (afk.kick_after_login: false).

7. ПРОКСИ (Velocity / BungeeCord / Waterfall и форки)
   * Тот же jar — в plugins/ прокси. Его настройки: plugins/vtregister/config.yml
     (Velocity) или plugins/VTRegister/config.yml (BungeeCord).
   * auth_servers — имя сервера из velocity.toml, где стоит VTRegister.
     Нет такого имени — игроков не кикает, но консоль каждую минуту
     напоминает, что прокси не настроен.
   * До входа прокси запрещает /server и смену сервера; после входа может
     сам отправить на after_login_server.
   * На Paper-сервере включи переадресацию: Velocity — paper.yml
     settings.velocity-support (Paper ≤1.18.2) или config/paper-global.yml
     proxies.velocity (1.19+); BungeeCord — spigot.yml settings.bungeecord: true
     + BungeeGuard или proxy.firewall. Не настроено — сервер пишет об этом
     в консоль каждую минуту. Подробно — PROXY_SETUP.txt.

8. ОПТИМИЗАЦИЯ
   Мир проверки пустой, чанки не держатся в памяти; картинки пазла готовятся
   заранее в фоне; пароли хешируются не в главном потоке; лобби строится один
   раз и только в режиме lobby. Игрок появляется сразу на платформе входа
   (security.spawn_on_platform), а после проверки едет с арены прямо на неё —
   без лишних перелётов через основной мир. Проверить нагрузку: /spark profiler.

9. КОМАНДЫ
   /authadmin reload | status | info <ник> | unregister <ник> | setpw <ник> <пароль>
   /authadmin unban — снять баны IP  |  /authadmin setspawn <prelogin|postlogin|firstjoin>
   /authadmin testmail <почта> — проверить отправку писем
   /vtregister reload — перечитать настройки  |  /vtregister help — справка для игроков

11. ВЕРСИИ
   Ядро сервера: 1.13 → 1.21.x и новая нумерация Mojang 26.x (26.1, 26.2…) и
     новее. Проверено сборкой на API 1.13.2, 1.14.4, 1.15.2, 1.16.5, 1.21.4 и
     26.2 (новейшая стабильная). Блоков, которых нет в старой версии
     (фонарь, незерит, мёд…), — заменяются похожими автоматически.
   Java: плагин собран под Java 8 и работает на Java 8 … 25. Какая Java нужна,
     решает ядро: 1.13–1.16 — 8+, 1.17 — 16+, 1.18–1.20.4 — 17+,
     1.20.5–1.21.x — 21+, 26.x — 25.
   Ядро 1.8–1.12 не поддерживается (другой набор блоков и карт). Нужны
     старые клиенты — ставь ядро 1.13+ и ViaVersion + ViaBackwards (+ ViaRewind
     для 1.7): игроки 1.7–1.12 заходят как обычно.

10. ЦЕЛОСТНОСТЬ СБОРКИ И МЕТКА ПОКУПАТЕЛЯ
   Сборка для конкретного покупателя: BUYER=имя bash tools/build.sh — имя
   зашивается в подписанный код (в консоли при старте: «сборка <имя>»).
   Правка метки ломает подпись — jar не запустится.
   Официальные сборки — только GitHub Releases:
   github.com/Vitaliy222121/VTRegister/releases (код открыт). Повреждённая или
   перепакованная сборка не запустится (в консоли: «сборка повреждена») —
   скачай оригинал оттуда.
