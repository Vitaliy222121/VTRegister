================================================================================
 VTRegister — ПОЛНАЯ ИНСТРУКЦИЯ ПО АНТИБОТУ, ОЧЕРЕДИ И ЛОББИ (RU)
================================================================================

1. КАК УСТРОЕНА ПРОВЕРКА НА БОТА
--------------------------------------------------------------------------------
Игрок при заходе попадает в отдельный пустой мир `auth_verify` и проходит
этапы подряд (каждый включается в config.yml → antibot.stages):

  fall    — плагин подбрасывает игрока на случайную высоту, он должен реально
            упасть на платформу. Платформы бывают с особой физикой:
            SLIME — клиент обязан отскочить вверх, COBWEB — медленное
            погружение, HONEY — мягкое приземление. Боты это не воспроизводят.
  camera  — накопить N полных оборотов камеры (camera_turns). Можно медленно,
            с паузами, в любую сторону. camera_linearity кикает роботов,
            которые крутят с идеально одинаковой дельтой.
  slots   — переключить слот хотбара slots_required раз. Плюс античит:
            сервер САМ меняет слот и ждёт реальную смену (grace-период
            slot_grace_millis спасает от ложных киков по пингу).
            Во время этапа камера дёргается slot_camera_jolts раз — живой
            клиент отвечает Look-пакетами, бот — нет.
  captcha — написать код из чата.
  click   — нажать на сообщение в чате.
  puzzle  — «убери лишних»: GUI с животными, убрать только целевых
            (puzzle_remove), потом написать в чат слово puzzle_confirm_word
            (по умолчанию "vse") — идёт проверка 3…2…1.
  math    — пример в чате/боссбаре (math_where), ответ в чат. Выкл по умолчанию.
  secret  — написать в чат точную строку (.bind, #help, свои или случайные —
            secret_mode: default|custom|random). Чит-клиенты перехватывают
            такие команды и не отправляют их в чат. Выкл по умолчанию.
  block   — пройти по СЛУЧАЙНОМУ зигзаг-пути (block_path_length), взять
            спец-инструмент из сундука (block_tool_chest), сломать целевой
            блок и подобрать дроп. Падение с пути: block_max_falls попыток,
            дальше кик.

Дополнительно фоново: packet_check (лимит move-пакетов за тик),
kick_flyers (полёт там, где нельзя = кик), таймауты на каждый этап.

2. ОЧЕРЕДЬ (queue_mode)
--------------------------------------------------------------------------------
Если проверок больше max_concurrent_checks — игроки встают в очередь.

  none    — стоят на месте, только сообщение с позицией.
  bossbar — + боссбар «Очередь: N/M» сверху.
  lobby   — общая ПЛАТФОРМА-ОЖИДАНИЕ: игроки гуляют, паркур 3 уровней,
            боссбар с позицией + голограмма со счётчиком, напоминания
            в чат раз в queue_spam_seconds сек. Провал = возврат без урона.

Настройки очереди: queue_max_size (лимит онлайна, 0=без), queue_chat_allowed
(чат видят только ждущие), queue_hide_players (скрыть друг друга),
queue_flight (летать в лобби), queue_kick_flyers (кик читеров-флаеров).

3. PvP-ЗОНА В ЛОББИ (queue_pvp)
--------------------------------------------------------------------------------
Прямоугольная зона по координатам corner1/corner2 (в мире проверки).
Внутри можно драться, снаружи урон отменяется. Сундук на chest_x/chest_z
пополняется каждые chest_seconds секунд лутом из списка items:

  "МАТЕРИАЛ[:ЗАЧАРОВАНИЕ:УРОВЕНЬ][:КОЛ-ВО]"
  пример: "NETHERITE_CHESTPLATE:PROTECTION:25"
          "DIAMOND_SWORD:SHARPNESS:1"
          "GOLDEN_APPLE:25"        ← 2 поля = материал + количество

4. СВОЯ ПЛАТФОРМА/СХЕМАТИКА ЛОББИ
--------------------------------------------------------------------------------
Хочешь своё лобби вместо стандартной платформы?

  1. queue_build_lobby: false  — плагин не строит ничего (кроме голограммы).
  2. Построй/вставь свою схематику в мире auth_verify вокруг точки
     (0, ~65, -512) — там спавн лобби. WorldEdit: //schem load lobby,
     //paste в нужной точке.
  3. Паркур/PvP-зону тоже можно построить вручную — координаты PvP-зоны
     всё равно задаются в конфиге и работают на любой постройке.

5. АВАРИЙНЫЙ РЕЖИМ
--------------------------------------------------------------------------------
Если мир проверки не создаётся — плагин НЕ пропускает ботов молча:
  - fallback_main_world: true  → арена строится высоко в небе основного мира.
  - В консоль спамится предупреждение: emergency.alert_times раз каждые
    emergency.alert_interval_seconds секунд (по умолчанию 10 раз / 5 мин).

6. БОССБАРЫ
--------------------------------------------------------------------------------
  bossbar: true          — прогресс проверки + отсчёт.
  bossbar_color: auto    — цвет по этапу ИЛИ фиксированный (BLUE/RED/...).
  bossbar_title: ""      — свой шаблон с {stage_num} {stage_total} {seconds}.
  bossbar2_enabled       — второй (рекламный) бар, bossbar2_title/color.

7. PROXY (BungeeCord/Velocity)
--------------------------------------------------------------------------------
Очередь локальная на каждом сервере (queue_proxy_sync резервирует слот).
Перенаправлять ЖДУЩИХ на другой сервер НЕЛЬЗЯ — очередь живёт только там,
где идёт проверка. После прохождения проверки игрока можно перекинуть
в лобби сети через proxy_server (см. config.yml).

8. ОПТИМИЗАЦИЯ
--------------------------------------------------------------------------------
  - Один общий тикер (10 тиков) на всех проверяемых и очередь — без
    отдельных задач на игрока.
  - Мир проверки пустой (VoidGenerator), autoSave off, keepSpawnInMemory off.
  - Арены переиспользуются (bounded slots), состояние чистится при
    выходе/кике/таймауте/прохождении.
  - Голограмма и боссбары обновляются раз в тик, не чаще.
