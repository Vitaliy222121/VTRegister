================================================================================
 VTRegister — настройка: один сервер, Velocity, BungeeCord, HAProxy, Geyser
================================================================================

Один и тот же jar работает везде:
  * Paper/Spigot/Folia-сервер — регистрация, пароли, антибот, 2FA
    (папка plugins/VTRegister/config.yml);
  * Velocity — прокси-модуль (plugins/vtregister/config.yml);
  * BungeeCord/Waterfall/форки — прокси-модуль (plugins/VTRegister/config.yml).

СОДЕРЖАНИЕ
  0. Как понять, что всё настроено (строка «Окружение» в логе)
  1. Один сервер без прокси
  2. Paper за Velocity (modern forwarding) — рекомендуемый вариант
  3. Paper за BungeeCord / Waterfall / форками
  4. HAProxy / TCPShield / другие L4-защиты перед сервером
  5. Geyser + Floodgate на прокси (Bedrock-игроки)
  6. Прокси-модуль: тот же jar на Velocity/BungeeCord
  7. Несколько серверов с VTRegister: общий секрет и общая БД
  8. Частые проблемы
  9. Справочник ключей

--------------------------------------------------------------------------------
0. КАК ПОНЯТЬ, ЧТО ВСЁ НАСТРОЕНО
--------------------------------------------------------------------------------
При старте и после /authadmin reload сервер пишет одну строку:

  Окружение: прокси включён (velocity), источник: paper.yml,
  IP-forwarding: Velocity modern, IP игроков: доверяем, премиум по UUID: разрешён

Что важно:
  * «IP игроков: НЕ доверяем» — лимиты, баны и сессии по IP ОТКЛЮЧЕНЫ
    (иначе один бан заблокировал бы всю сеть, а IP можно подделать).
  * «премиум по UUID: запрещён» — premium.enabled не действует, все вводят
    пароль. Причина — UUID игрока можно подделать (см. раздел 3).
  * Строки SEVERE/WARNING рядом с «Окружение» прямо называют ключ,
    который нужно исправить.

Плагин сам читает настройки ядра из корня сервера:
  spigot.yml                settings.bungeecord               — BungeeCord legacy;
  paper.yml                 settings.velocity-support.enabled — Velocity, Paper 1.13–1.18.2;
  config/paper-global.yml   proxies.velocity.enabled          — Velocity, Paper 1.19+.
Ручное переопределение — config.yml → proxy.type:
  auto (по умолчанию) | velocity | bungeecord | none (прокси нет, перенос выключен).
Ручной тип не делает forwarding доверенным: доверие считается только по
настройкам ядра и защитам из раздела 3.

--------------------------------------------------------------------------------
1. ОДИН СЕРВЕР БЕЗ ПРОКСИ
--------------------------------------------------------------------------------
Ничего настраивать не нужно:
  * spigot.yml → settings.bungeecord: false;
  * Velocity в paper.yml / paper-global.yml выключен;
  * config.yml → proxy.type: "auto" (или "none");
  * proxy_server.enabled: false, proxy.firewall.enabled: false.

premium.enabled имеет смысл только при online-mode=true в server.properties
(на пиратском сервере UUID лицензии не совпадёт — эффекта не будет).

--------------------------------------------------------------------------------
2. PAPER ЗА VELOCITY (MODERN FORWARDING) — РЕКОМЕНДУЕТСЯ
--------------------------------------------------------------------------------
Modern forwarding подписан секретом: подделать IP/UUID, подключившись
к порту сервера напрямую, нельзя. Это единственный вариант, где премиум-
автологин и проверки по IP работают без дополнительных плагинов.
Требования: Paper 1.13+ и клиенты 1.13+ (для старых клиентов — раздел 3).

2.1. velocity.toml:
       player-info-forwarding-mode = "modern"
       forwarding-secret-file = "forwarding.secret"   # файл с длинной случайной строкой
       bungee-plugin-message-channel = true            # нужен для переноса в лобби
       [servers]
         auth  = "127.0.0.1:25566"
         lobby = "127.0.0.1:25567"
         try = ["auth"]

2.2. Каждый Paper-сервер:
       server.properties:  online-mode=false
       spigot.yml:         settings.bungeecord: false      (ОБЯЗАТЕЛЬНО false!)

     Paper 1.13 – 1.18.2 — файл paper.yml в корне сервера:
       settings:
         velocity-support:
           enabled: true
           online-mode: true            # true, если Velocity в online-mode
           secret: "<содержимое forwarding.secret>"

     Paper 1.19 и новее — файл config/paper-global.yml:
       proxies:
         velocity:
           enabled: true
           online-mode: true
           secret: "<содержимое forwarding.secret>"

2.3. VTRegister на Paper (plugins/VTRegister/config.yml):
       proxy:
         type: "auto"                   # определится как velocity
       premium:
         enabled: true                  # только если Velocity в online-mode
     Перенос в лобби после входа — выберите ОДИН способ:
       а) прокси-модуль (раздел 6): after_login_server: [lobby] на прокси,
          а на Paper proxy_server.enabled: false;
       б) без модуля: на Paper
            proxy_server:
              enabled: true
              server_name: "lobby"      # имя из [servers] velocity.toml

2.4. Порт Paper-серверов лучше закрыть от интернета (слушать 127.0.0.1 или
     закрыть файрволом ОС). Для Velocity modern это не обязательно для
     безопасности, но убирает мусорные подключения.

--------------------------------------------------------------------------------
3. PAPER ЗА BUNGEECORD / WATERFALL / ФОРКАМИ
--------------------------------------------------------------------------------
ВНИМАНИЕ: legacy-forwarding BungeeCord НЕ подписан. Если порт Paper-сервера
доступен из интернета, любой клиент подключается к нему напрямую и сам пишет
в хендшейк любой IP и любой UUID (например, UUID лицензии админа). Поэтому
без одной из защит ниже VTRegister сам ОТКЛЮЧАЕТ премиум-автологин, IP-сессии
и лимиты/баны по IP и пишет SEVERE в лог.

3.1. config.yml прокси:
       ip_forward: true
       servers:
         auth:  { address: 127.0.0.1:25566, restricted: false }
         lobby: { address: 127.0.0.1:25567, restricted: false }
       listeners:
         - priorities: [auth]

3.2. Каждый Paper-сервер:
       server.properties:  online-mode=false
       spigot.yml:         settings.bungeecord: true

3.3. ОБЯЗАТЕЛЬНО одна из защит (лучше две):
     а) BungeeGuard — плагин на прокси И на каждом Paper-сервере с одинаковым
        токеном. VTRegister видит плагин BungeeGuard и доверяет forwarding.
     б) Файрвол VTRegister — пускать на сервер только подключения с IP прокси:
          proxy:
            firewall:
              enabled: true
              allowed_ips:
                - "127.0.0.1"          # прокси на той же машине
                # - "10.0.0.5"         # или IP прокси, как его видит сервер
                # - "10.0.0.0/24"      # можно подсеть (CIDR)
        IP указывается таким, каким сервер видит подключение ПРОКСИ (адрес
        сокета), а не IP игроков. Неверный IP = никто не зайдёт: проверьте по
        строке «Proxy-firewall: отклонено прямое подключение ... с <IP>».
        «0.0.0.0», «*» и «/0» защитой не считаются.
     в) Файрвол ОС (iptables/ufw/панель хостинга): порт Paper открыт только для
        IP прокси. Плагин этого не видит — дополнительно включите (а) или (б),
        иначе премиум и проверки по IP останутся выключенными.

3.4. Ключа proxy_security в VTRegister НЕТ (он был в старой инструкции и ни на
     что не влиял). Защита — только proxy.firewall / BungeeGuard / Velocity.

--------------------------------------------------------------------------------
4. HAPROXY / TCPSHIELD / ДРУГИЕ L4-ЗАЩИТЫ ПЕРЕД СЕРВЕРОМ
--------------------------------------------------------------------------------
Такие сервисы стоят перед прокси (или перед единственным сервером). Без
PROXY protocol у ВСЕХ игроков будет IP защиты.

  * Перед Velocity:   velocity.toml → haproxy-protocol = true
  * Перед BungeeCord: config.yml прокси → listeners: proxy_protocol: true
  * Перед одиночным Paper: PROXY protocol в настройках ядра
    (на новых Paper — paper-global.yml proxies.proxy-protocol) или плагин
    сервиса (например, TCPShield). В этом варианте НЕ включайте
    proxy.firewall — сервер видит уже IP игроков, а не IP защиты.

Если настоящие IP до прокси не доходят, выключите лимиты по IP на прокси-модуле
(connection_limit.per_ip_per_minute: 0, max_online_per_ip: 0) и добавьте IP
защиты в proxy.known_proxy_ips на Paper-серверах — с этих адресов VTRegister
не применяет лимиты, баны и IP-сессии.

--------------------------------------------------------------------------------
5. GEYSER + FLOODGATE НА ПРОКСИ (BEDROCK-ИГРОКИ)
--------------------------------------------------------------------------------
  * Geyser и Floodgate ставятся на прокси; Floodgate — ещё и на каждый Paper-
    сервер с тем же key.pem (иначе сервер не узнает, что игрок Bedrock).
  * Ники Bedrock приходят с префиксом Floodgate (по умолчанию «.Steve»).
    Фильтр ников VTRegister (antibot.guard.name_regex) такие ники пропускает:
    префикс «.»/«*» или username-prefix из plugins/floodgate/config.yml
    отрезается, а игроки с Floodgate-UUID фильтр не проходят вовсе.
  * Вход Bedrock без пароля — bedrock.enabled: true и
    bedrock.trust_floodgate_players: true (только при Floodgate на сервере).
  * Если Geyser стоит на машине прокси без PROXY protocol, у всех
    Bedrock-игроков адрес 127.0.0.1 — прокси-модуль не применяет к loopback
    лимиты по IP, а на Paper адрес прокси входит в proxy.known_proxy_ips.

--------------------------------------------------------------------------------
6. ПРОКСИ-МОДУЛЬ: ТОТ ЖЕ JAR НА VELOCITY / BUNGEECORD
--------------------------------------------------------------------------------
Зачем: сервер не может сам запретить смену сервера через прокси. Модуль:
  * не пускает на другие серверы, пока игрок не вошёл (/server, фолбэк, меню);
  * блокирует прокси-команды до входа (кроме allowed_proxy_commands);
  * после входа отправляет на after_login_server;
  * режет бот-волны по настоящим IP ещё на прокси (connection_limit);
  * переносит вход между серверами с VTRegister (при общем secret).

Установка:
  1) Положите тот же VTRegister.jar в plugins/ прокси и перезапустите его.
  2) Появится конфиг: Velocity — plugins/vtregister/config.yml,
     BungeeCord/Waterfall — plugins/VTRegister/config.yml.
  3) Заполните:
       auth_servers: [auth]          # серверы, где стоит VTRegister и вводят пароль
       after_login_server: [lobby]   # куда после входа ([] — остаться)
       allowed_proxy_commands: []    # прокси-команды до входа, без '/'
       secret: 'длинная-случайная-строка'
  4) На КАЖДОМ Paper-сервере с VTRegister (plugins/VTRegister/config.yml):
       security:
         proxy_bridge:
           enabled: true
           secret: 'та-же-самая-строка'
           trust_network_login: true
  5) Если используете after_login_server — на Paper proxy_server.enabled: false
     (иначе игрока отправят дважды).

Как это работает: после входа (пароль, регистрация, премиум, IP-сессия,
Bedrock, /authadmin forcelogin) сервер шлёт прокси AUTH по каналу
vtregister:main; только после этого прокси разрешает смену сервера. Перенос
на другой сервер ДО входа не выполняется никогда.
Секрет: сообщения подписаны HMAC-SHA256, клиент их подделать не может.
Разный secret на прокси и сервере = игроки не смогут уйти с сервера входа
(в логе прокси: «подпись моста от сервера не сошлась»). Часы прокси и
серверов должны совпадать с точностью до 30 секунд (NTP).
Мост работает, только когда сервер видит, что он за прокси (строка
«Окружение: прокси включён»).

--------------------------------------------------------------------------------
7. НЕСКОЛЬКО СЕРВЕРОВ С VTREGISTER
--------------------------------------------------------------------------------
Рекомендуемая схема: VTRegister только на сервере входа (auth), на остальных
серверах плагина нет, а попасть на них до входа не даёт прокси-модуль.

Если VTRegister стоит на нескольких серверах:
  * общая БД (advanced.yml → storage.type: mysql / mariadb / postgresql) —
    один аккаунт на всю сеть;
  * одинаковый secret в прокси-модуле и в security.proxy_bridge.secret на всех
    серверах — игрок, вошедший на одном сервере, на другом входит без пароля
    (прокси присылает подписанный TRUST);
  * без secret каждый сервер спрашивает пароль сам.

--------------------------------------------------------------------------------
8. ЧАСТЫЕ ПРОБЛЕМЫ
--------------------------------------------------------------------------------
«После /login игрок остаётся на сервере входа»
  - в строке «Окружение» прокси выключен → проверьте paper.yml /
    paper-global.yml / spigot.yml (разделы 2–3) или задайте proxy.type;
  - Velocity: bungee-plugin-message-channel = true;
  - имя в proxy_server.server_name / after_login_server совпадает с именем в
    конфиге прокси;
  - стоит прокси-модуль, а secret различается (см. раздел 6).

«Слишком много подключений с твоего IP» у всех игроков
  - IP-forwarding не работает: у всех адрес прокси. Включите forwarding
    (разделы 2–3). До исправления добавьте IP прокси в proxy.known_proxy_ips.

«Подключение напрямую запрещено» у всех
  - в proxy.firewall.allowed_ips не тот IP прокси. Смотрите IP в строке
    «Proxy-firewall: отклонено прямое подключение ... с <IP>».

«Премиум-автологин не работает за прокси»
  - это защита: forwarding не защищён (раздел 3.3) или секрет Velocity пуст.

«Bedrock-игроков кикает за ник»
  - если меняли name_regex вручную: префикс Floodgate отрезается
    автоматически, остаток ника должен подходить под регулярку.

«Игрока с таким ником уже на сервере»
  - security.single_session: ник уже в игре и вошёл в аккаунт — второе
    подключение отклоняется, играющего не выбивает. Выйдите с первого клиента.

9. СПРАВОЧНИК КЛЮЧЕЙ (Paper, plugins/VTRegister/config.yml)
--------------------------------------------------------------------------------
proxy.type                         auto | velocity | bungeecord | none
proxy.known_proxy_ips              адреса прокси/защиты: без лимитов, банов и IP-сессий
proxy.firewall.enabled             пускать только с allowed_ips
proxy.firewall.allowed_ips         IP/подсети прокси (как их видит сервер)
proxy_server.enabled               перенос в лобби силами сервера (без модуля)
proxy_server.server_name           имя лобби в конфиге прокси
security.single_session            ник уже в игре и вошёл → новое подключение
                                   с этим ником отклоняется
security.proxy_bridge.enabled      мост с прокси-модулем
security.proxy_bridge.secret       общий секрет с прокси-модулем
security.proxy_bridge.trust_network_login
                                   вход без пароля по подписанному TRUST с прокси
premium.enabled                    премиум по UUID (только при доверенном UUID)
